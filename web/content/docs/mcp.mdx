boot 服务内置 MCP Server，端点为 `/mcp`，协议为 Streamable HTTP。
部署后端点跟随当前地址，Jar 与 Docker 默认为 `http://127.0.0.1:8080/mcp`。

## 可用工具

| 工具 | 说明 |
| --- | --- |
| `memshell_capabilities` | 列出全部 server、shellTool、shellType、packer、探测方式、混淆参数与混淆范围 |
| `generate_memshell` | 在服务端直接生成内存马，返回 `memShellResult` 与 `packResult`；请求参数与 `POST /api/memshell/generate` 一致，支持 Godzilla、Behinder、AntSword、Suo5、Command 等 |
| `generate_probe_shell` | 在服务端直接生成探测马，返回 `probeShellResult` 与 `packResult`；请求参数与 `POST /api/probe/generate` 一致，支持 DNSLog、ResponseBody、ResponseHeader、Sleep |

> 建议先调用 `memshell_capabilities` 获取合法参数，再调用生成工具。生成在 MCP 服务内完成，payload 直接出现在工具结果中，不需要再发起 REST 请求，因此 MCP 与 REST 可以使用各自独立的凭据。

## 认证

默认 `OFF` 模式不需要凭据。启用 `ADMIN` 或 `PLATFORM` 后，每次 MCP HTTP 请求都必须携带凭据，包括初始化、列出工具、调用工具和后续会话请求。

`ADMIN` 使用启动日志中生成的随机密码，为每次请求添加 HTTP Basic 请求头：

```bash
claude mcp add --transport http memshell-party http://127.0.0.1:8080/mcp \
  --header "Authorization: Basic <base64(admin:启动日志中的密码)>"
```

`PLATFORM` 的 Claude Code 请求头配置示例。示例假设 `platform.mcp.auth-param=x_token`：

```bash
claude mcp add --transport http memshell-party http://127.0.0.1:8080/mcp \
  --header "x_token: <平台令牌>"
```

请求头名称必须与 `memshell-party.auth.platform.mcp.auth-param` 一致。服务把令牌转发到 `memshell-party.auth.platform.mcp.sign-url`，只有平台响应为 2xx 且响应体包含 `sign-success-res` 时才继续。该地址为 HTTPS 时不校验证书，自签名证书也可以使用。完整配置见[自托管部署](/docs/self-host#platform)。

请求头不存在时，也可以携带同名查询参数，例如 `http://127.0.0.1:8080/mcp?x_token=<平台令牌>`。请求头存在但为空、重复或错误时返回 403，正确的查询参数不能补救。

MCP 与 REST 分开校验。MCP 使用 `platform.mcp.*`，直接调用 REST API 时使用 `platform.rest.*`，两者可以指向同一个平台接口。MCP 生成工具不依赖 REST 凭据。

查询参数令牌可能进入 URL、访问日志和命令历史，优先使用请求头，并在非回环地址部署中使用 HTTPS。

## 调用流程

1. 调用 `memshell_capabilities`，获取合法的 server、shellTool、shellType、packer 等取值。
2. 调用 `generate_memshell` 或 `generate_probe_shell`，生成在服务端完成，直接返回 `packResult` 与结果元数据。
3. 按需读取结果字段，例如 `memShellResult.shellClassName`、`memShellResult.injectorConfig` 与 `packResult`。

示例指令：

```
先调用 memshell_capabilities 获取合法参数，再调用 generate_memshell 直接生成 payload，并读取结果中的类名与 packResult。
```
