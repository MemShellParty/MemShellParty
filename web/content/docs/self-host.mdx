## Docker 部署

> 适合内网或本地快速部署，直接使用 Docker 启动服务方便快捷

使用 docker 部署之后，使用浏览器访问：http://127.0.0.1:8080

<Tabs
  items={["Docker Hub 源", "Github Container Registry 源", "南大 Github Container Registry 镜像源"]}
>
  <Tab>
    ```bash
    docker run --pull=always --rm -it -d -p 8080:8080 --name memshell-party reajason/memshell-party:latest
    ```
  </Tab>
  <Tab>
    ```bash
    docker run --pull=always --rm -it -d -p 8080:8080 --name memshell-party ghcr.io/memshellparty/memshell-party:latest
    ```
  </Tab>
  <Tab>
    ```bash
    docker run --pull=always --rm -it -d -p 8080:8080 --name memshell-party ghcr.nju.edu.cn/memshellparty/memshell-party:latest
    ```
  </Tab>
</Tabs>

镜像是无状态的，在需要更新最新镜像时，直接移除新建就好了

```bash
# 移除之前部署的
docker rm -f memshell-party

# 使用之前的部署命令重新部署（会自动拉取最新的镜像部署）
docker run --pull=always --rm -it -d -p 8080:8080 --name memshell-party reajason/memshell-party:latest
```

## Jar 包部署

下载最新 [release](https://github.com/MemShellParty/MemShellParty/releases) 的 memshell-party-boot-x.x.x.jar 包

使用 JDK17 启动 jar 包，并使用浏览器访问：http://127.0.0.1:8080

```bash
java -jar --add-opens=java.base/java.util=ALL-UNNAMED \
        --add-opens=java.xml/com.sun.org.apache.xalan.internal.xsltc.trax=ALL-UNNAMED \
        --add-opens=java.xml/com.sun.org.apache.xalan.internal.xsltc.runtime=ALL-UNNAMED \
        memshell-party-boot-x.x.x.jar
```

如果存在端口冲突，需要自定义服务端口，使用如下命令： `--server.port=自定义端口`

```bash
java -jar --add-opens=java.base/java.util=ALL-UNNAMED \
        --add-opens=java.xml/com.sun.org.apache.xalan.internal.xsltc.trax=ALL-UNNAMED \
        --add-opens=java.xml/com.sun.org.apache.xalan.internal.xsltc.runtime=ALL-UNNAMED \
        memshell-party-boot-x.x.x.jar --server.port=9999
```

## 认证

认证覆盖 UI、REST、MCP 和文档数据请求，静态资源 `/assets/**` 与 favicon 允许匿名访问。默认值为 `OFF`，上述 Docker 与 Jar 默认启动命令不变，也不需要提供任何凭据。如需显式关闭，可设置 `--memshell-party.auth.mode=OFF`。`ADMIN` 认证失败返回 401，`PLATFORM` 认证失败返回 403。

Docker 环境变量使用 Spring Boot relaxed binding：

| 配置 | Docker 环境变量 |
| --- | --- |
| `memshell-party.auth.mode` | `memshell-party_auth_mode` |
| `memshell-party.auth.platform.rest.auth-param` | `memshell-party_auth_platform_rest_authparam` |
| `memshell-party.auth.platform.rest.sign-url` | `memshell-party_auth_platform_rest_signurl` |
| `memshell-party.auth.platform.rest.sign-param` | `memshell-party_auth_platform_rest_signparam` |
| `memshell-party.auth.platform.rest.sign-header` | `memshell-party_auth_platform_rest_signheader` |
| `memshell-party.auth.platform.rest.sign-success-res` | `memshell-party_auth_platform_rest_signsuccessres` |
| `memshell-party.auth.platform.mcp.auth-param` | `memshell-party_auth_platform_mcp_authparam` |
| `memshell-party.auth.platform.mcp.sign-url` | `memshell-party_auth_platform_mcp_signurl` |
| `memshell-party.auth.platform.mcp.sign-param` | `memshell-party_auth_platform_mcp_signparam` |
| `memshell-party.auth.platform.mcp.sign-header` | `memshell-party_auth_platform_mcp_signheader` |
| `memshell-party.auth.platform.mcp.sign-success-res` | `memshell-party_auth_platform_mcp_signsuccessres` |

以下 Jar 示例省略了上述 `--add-opens` 参数，实际启动时应保留这些参数。

### ADMIN

`ADMIN` 只有一个用户，固定用户名为 `admin`。每次启动都会生成新的随机密码，密码只出现在启动日志中，不支持固定密码配置。

Docker：

```bash
docker run --pull=always --rm -d -p 8080:8080 \
  --env 'memshell-party_auth_mode=ADMIN' \
  --name memshell-party reajason/memshell-party:latest

docker logs memshell-party
```

Jar：

```bash
java -jar memshell-party-boot-x.x.x.jar --memshell-party.auth.mode=ADMIN
```

在日志中找到 `Generated admin password for user 'admin'` 后面的密码。浏览器会显示原生 Basic 认证提示；命令行使用：

```bash
curl --user 'admin:<启动日志中的密码>' http://127.0.0.1:8080/api/config
```

### PLATFORM

`PLATFORM` 把凭据校验交给接入方平台。memshell-party 从请求中取出凭据，再向平台配置的校验地址发起 GET 请求。只有校验响应为 2xx 且响应体包含成功标志时，请求才会继续。未携带凭据、平台拒绝、超时或非 2xx 响应都返回 403。

REST/UI 与 MCP 分开配置：`platform.rest.*` 保护 `/ui`、`/api` 和文档数据请求，`platform.mcp.*` 保护 `/mcp`。每个作用域包含四个配置：

- `auth-param`：入站凭据名称。请求带同名请求头时只校验请求头，否则校验原始 URL 中的同名查询参数。空值、重复值或错误值都返回 403，正确的查询参数不能补救错误的请求头。表单请求体中的同名参数不能用于认证。
- `sign-url`：校验地址，必须是绝对的 http 或 https URL。
- `sign-param` 或 `sign-header`：二选一，不能同时配置。`sign-param` 把凭据拼接到校验地址的查询字符串，`sign-header` 把凭据放入请求头。
- `sign-success-res`：成功标志，按原始响应体做子串匹配。它可以是任意稳定片段，例如 `"code":1`。平台输出带空格或换行时，标志必须与响应字节完全一致。

以下示例使用平台的 `baseInfo` 接口校验 `x_token`：

```bash
java -jar memshell-party-boot-x.x.x.jar \
  --memshell-party.auth.mode=PLATFORM \
  --memshell-party.auth.platform.rest.auth-param=x_token \
  --memshell-party.auth.platform.rest.sign-url='https://platform.example.com/internalApi/adminUser/baseInfo' \
  --memshell-party.auth.platform.rest.sign-param=x_token \
  '--memshell-party.auth.platform.rest.sign-success-res="code":1' \
  --memshell-party.auth.platform.mcp.auth-param=x_token \
  --memshell-party.auth.platform.mcp.sign-url='https://platform.example.com/internalApi/adminUser/baseInfo' \
  --memshell-party.auth.platform.mcp.sign-param=x_token \
  '--memshell-party.auth.platform.mcp.sign-success-res="code":1'
```

Docker 使用对应环境变量：

```bash
docker run --pull=always --rm -d -p 8080:8080 \
  --env 'memshell-party_auth_mode=PLATFORM' \
  --env 'memshell-party_auth_platform_rest_authparam=x_token' \
  --env 'memshell-party_auth_platform_rest_signurl=https://platform.example.com/internalApi/adminUser/baseInfo' \
  --env 'memshell-party_auth_platform_rest_signparam=x_token' \
  --env 'memshell-party_auth_platform_rest_signsuccessres="code":1' \
  --env 'memshell-party_auth_platform_mcp_authparam=x_token' \
  --env 'memshell-party_auth_platform_mcp_signurl=https://platform.example.com/internalApi/adminUser/baseInfo' \
  --env 'memshell-party_auth_platform_mcp_signparam=x_token' \
  --env 'memshell-party_auth_platform_mcp_signsuccessres="code":1' \
  --name memshell-party reajason/memshell-party:latest
```

浏览器入口把平台令牌放在 `auth-param` 指定的查询参数中：

```bash
http://127.0.0.1:8080/ui/?x_token=<平台令牌>
```

站内导航和后续 REST 请求会保留该查询参数。也可以使用同名请求头：

```bash
curl -H 'x_token: <平台令牌>' http://127.0.0.1:8080/api/config
```

每个受保护请求都会触发一次平台校验请求。静态资源 `/assets/**` 和 favicon 不校验，令牌不会写入日志或接口响应。

查询参数令牌可能进入 URL、浏览器历史、代理与访问日志、命令历史和监控数据。生产环境应使用 HTTPS，限制直接访问应用端口。反向代理应负责 TLS 终止。
